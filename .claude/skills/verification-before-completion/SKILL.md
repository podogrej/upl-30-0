# Verification before completion

Нельзя сказать «готово», «починено» или «тесты проходят», пока в этом же сообщении не запущена проверка и не прочитан её вывод.

## Порядок

1. Определи команду, которая доказывает утверждение.
2. Запусти её целиком, свежей, не из памяти и не из прошлого прогона.
3. Прочитай весь вывод: код возврата, число упавших.
4. Если вывод не подтверждает, назови реальное состояние с выводом. Если подтверждает, назови результат вместе с доказательством.

## Что считается доказательством

| Утверждение | Нужно | Не годится |
|---|---|---|
| Тесты проходят | вывод тестов, 0 упавших | прошлый прогон, «должно пройти» |
| Линтер чистый | вывод линтера, 0 ошибок | частичная проверка |
| Сборка успешна | команда сборки, код 0 | «линтер прошёл» |
| Баг исправлен | воспроизведён исходный симптом, теперь не воспроизводится | «поменял код» |
| Регрессионный тест рабочий | красный до фикса, зелёный после | один зелёный прогон |
| Исполнитель закончил | diff в git, проверены изменения и запущены тесты | отчёт «успешно» |
| Требования выполнены | чеклист по пунктам задачи | «тесты зелёные» |

## Для PM и ревьюера

Отчёту исполнителя не верим. Перед тем как двигать задачу дальше и звать человека на PR, смотрим diff и сами запускаем проверки. Если проверить нельзя, так и пишем: «не проверено, потому что …».

## Тревожные слова

«должно», «наверное», «похоже», «готово!» до запуска проверки. Увидел у себя, остановись и запусти.
