# 30-0 УПЛ

Драфт-игра по истории Прем'єр-ліги України (1992–2026). Колесо даёт клуб и сезон, игрок берёт оттуда одного футболиста, собирает XI и играет 30 туров. Цель — 30 побед из 30.

- **Сайт:** https://upl-30-0.vercel.app
- **Бот и мини-апп:** [@upl30_bot](https://t.me/upl30_bot)
- **Язык игры:** украинский. Техническая документация — на русском.

Запустить подсчёт вручную ссылкой `?key=…` больше нельзя.

**Как добавить `CRON_SECRET` (и `TG_SECRET` для Preview) — с iPad, один раз.** Значения никому не пересылать, в чат не вставлять.
1. Придумай секрет: в Safari на любой странице с полем пароля iPad предложит «Надёжный пароль» — скопируй его. Или любые 30+ случайных букв и цифр.
2. Открой vercel.com → проект **upl-30-0** → вкладка **Settings** → слева **Environment Variables**.
3. Нажми **Add New** (или «Add Environment Variable»): Key — `CRON_SECRET`, Value — вставь секрет. В **Environments** отметь **Production** и **Preview**. Нажми **Save**.
4. `TG_SECRET`: найди его в списке. Если у него стоит только Production — **не меняй значение для Production** (оно должно совпадать с вебхуком бота). Добавь ещё одну переменную `TG_SECRET` только для **Preview** с любым другим длинным значением (бот на тестовый сайт не ходит, секрет нужен, чтобы тестовый `/api/bot` был закрыт).
5. Переменные действуют только на новые сборки: вкладка **Deployments** → последняя сборка нужной ветки → **⋯** → **Redeploy**. Для прода это сделает мерж 0.52, для теста — любой новый пуш в `test` (или Redeploy).
6. Проверка: в Safari открой `https://upl-30-0.vercel.app/api/cron` — должно быть `{"error":"unauthorized"}`. Это правильно: вызвать подсчёт может только Vercel Cron. Бот в Telegram отвечает на `/top` как раньше.

## Telegram-канал (с 0.69.97)

Бот @upl30_bot — админ канала об истории УПЛ. Посты — очередь в таблице `channel_posts` (`sql/v06997_channel_posts.sql`, обе базы), код — `api/_channel.js`.

**Схема `channel_posts`** (на неё опирается отдельная сессия, которая пишет посты — не менять без нужды):

| Поле | Что |
|---|---|
| `id` | identity |
| `text` | HTML-разметка Telegram (`<b>`, `<i>`, `<a href>`…); видимого текста ≤ 4096, с картинкой ≤ 1024 (проверка в базе) |
| `image_url` | необязательно: адрес картинки или `file_id` из Telegram |
| `publish_at` | timestamptz — с какого момента черновик показывается владельцу на одобрение |
| `status` | `draft` → `pending_approval` (превью у владельца) → `published` или `rejected`; `failed` — Telegram не принял, можно повторить |
| `source` | `chat` (сессия Claude), `owner` (владелец через бота), `auto` (сервер) |
| `created_at`, `published_at`, `tg_message_id`, `error` | служебное (`tg_message_id` — номер поста в канале) |

RLS включён, политик нет, права anon/authenticated отозваны: читает и пишет только сервер (ключ `SUPABASE_SERVICE_KEY`, как у карточек и лиг) и владелец через Supabase.

**Как посты попадают в очередь:** строка `draft` прямо в базу (коннектор Supabase, `publish_at` — когда показать владельцу); `/post <текст>` боту в личку (или фото с подписью `/post <текст>`) — черновик с `publish_at = now()` и сразу превью; автопосты сервера (`auto`, тоже `draft`): анонс виклику дня из `lib/challenges.json` (готовится накануне после 18:00 по Киеву, только на день с вызовом, на одобрение в 9:00) и итоги недели (в понедельник после 8:00, на одобрение в 12:00), выключатель — `/auto off` / `/auto on`.
**Одобрение и публикация:** черновик с наступившим `publish_at` бот присылает владельцу в личку так, как он выйдет в канале, с кнопками «Опублікувати» и «Відхилити»; статус атомарно `draft → pending_approval`, поэтому дважды не присылает. «Опублікувати» — сразу в `CHANNEL_CHAT_ID` с `parse_mode=HTML` (с картинкой — фото с подписью), статус `published`, `tg_message_id`; повторное нажатие не публикует второй раз. «Відхилити» — `rejected`. Ошибка Telegram → `failed`, текст в `error`, кнопка «Спробувати ще». `/queue` — что ждёт решения. Команды и кнопки — только от `OWNER_TG_ID` в личке; `/whoami` — любому, отвечает его Telegram ID.
**Запуск очереди:** `/api/cron?task=channel` (ключ `CHANNEL_SECRET` или `CRON_SECRET`) — автопосты и превью наступивших черновиков. Vercel Hobby даёт Cron лишь раз в день, поэтому каждые 10 минут запуск идёт из GitHub Actions (`.github/workflows/channel.yml`, только из ветки `main`); раз в день — ещё и из вечернего `api/cron.js`. `/post` от запуска не зависит.
**Тест и прод:** бот один, вебхук — на проде. Основная база публикует только в `CHANNEL_CHAT_ID` и только с прода; тестовая — только в `TEST_CHANNEL_ID`. `/post test …`, `/queue test`, `/auto test off` — посты тестовой базы, с пометкой «ТЕСТ». Карточки (`TG_CARDS_CHAT`, закрытый канал) — отдельно, канал постов их не трогает.

## Сповіщення в боті (с 0.70)

Только по согласию игрока: `/notify` в личке бота (или ссылка `t.me/upl30_bot?start=notify` из «Налаштувань») — бот объясняет, что присылает, и даёт кнопку «Увімкнути»; по умолчанию выключено. Вечером (`api/cron.js`, Vercel Cron 18:00 UTC ≈ 21:00 по Киеву) — одно сообщение на игрока: место и очки в каждой лиге группы, где он играл сегодня, и «серия под угрозой», если виклик дня (до 0.80 — драфт дня) вчера был засчитан, а сегодня нет. Кнопка «Вимкнути сповіщення» в каждом сообщении; если игрок заблокировал бота — выключается сам. Код — `api/_notify.js`, согласия — таблица `tg_notify` (`sql/v070.sql`), новых переменных не нужно.

## Резервные копии базы (с 0.55)

Каждую ночь (~03:30 по Киеву) Vercel Cron вызывает `api/backup.js`: сервер своим ключом читает все важные таблицы (игроки и их связи, сезоны со составами и таблицами, результаты дня, трофеи, виклики, лиги групп, `user_state`, 5×5, `season_seeds` за 30 дней) и кладёт один сжатый файл `ГГГГ-ММ-ДД.json.gz` в **приватное** хранилище Supabase `backups` (SQL: `sql/v055_backups.sql`). Хранятся последние 14 дней и понеділки за 8 недель, старше — удаляются сами. Vercel Cron работает только на проде, поэтому копии — основной базы. Там же (с 0.67) удаляются картки для Telegram в публичном хранилище `cards` старше 7 дней.

**Как скачать копию (iPad):** supabase.com → проект основной базы → слева **Storage** → **backups** → нажми на файл с нужной датой → **Download**. Файл никому не пересылать: в нём все данные игроков.
**Как восстановить:** владелец не восстанавливает сам — пришли Claude дату (или файл) и что случилось; план — `tools/backup/restore_plan.md`.
**Проверка, что копии идут:** в Storage → backups есть файл за сегодня/вчера; или Vercel → проект → **Logs**, строка `backup {"ok":true…}` с числом строк по таблицам.

## Ограничение частоты (с 0.55)

`/api/seed`, `/api/save`, `/api/verify`, `/api/card`, `/api/auth` считают запросы в базе (`rate_hits`, функция `rate_hit` — только для сервера): за минуту на устройство — seed 20, save 40; на IP (из `x-forwarded-for`) — вчетверо больше, а для verify 30, card 10, auth 60 (вход через бота опрашивает раз в 2,5 с). Сверх лимита — 429 с украинским текстом, сайт показывает его под результатом, сезон всё равно играется (с локальным seed). Числа — `LIMITS` в `api/_device.js`. Счётчик в памяти функции не годится (экземпляров Vercel много). Если база недоступна или SQL 0.55 не выполнен — лимита нет.

## Как выпускаем версию

1. **Claude:**
   - правит `src/`;
   - поднимает номер в подвале («Що нового у версії X.YY» в `src/template.html`) и обновляет `WHATSNEW`;
   - собирает: `python3 src/build.py` и `node tools/make_engine.js`. Номер в подвале и `VERSION` в `lib/engine.js` должны совпасть;
   - прогоняет проверки (ниже);
   - обновляет CHANGELOG и BACKLOG;
   - отправляет в ветку `test`.
2. **SQL, если есть:** новый файл `sql/<что>.sql`. Claude присылает его в чат **блоком кода**. Владелец запускает сначала в тестовой базе, после мержа — в основной. Правила базы — DECISIONS, пункт 13: только добавляем.
3. **Claude** проверяет полностью (см. CLAUDE.md → «Выпуск»): `python3 data/check_pool.py` без ошибок, `determinism` 9/9, `scenarios` «УСЕ ГАРАЗД», тестовый сайт собрался. Если есть SQL — ждёт, пока владелец выполнит его в основной базе.
4. **Claude** делает pull request `test` → `main` и мержит его сам (решение владельца 29.09.2026). Прод собирается сам. Владелец может посмотреть тестовый сайт (метка «ТЕСТ») в любой момент.
5. **Проверка прода:** внизу upl-30-0.vercel.app — новая версия. Мини-апп в Telegram закрыть и открыть заново, иначе может показывать старую версию из кэша.
