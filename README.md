# 30-0 УПЛ

Драфт-игра по истории Прем'єр-ліги України (1992–2026). Колесо даёт клуб и сезон, игрок берёт оттуда одного футболиста, собирает XI и играет 30 туров. Цель — 30 побед из 30.

- **Сайт:** https://upl-30-0.vercel.app
- **Бот и мини-апп:** [@upl30_bot](https://t.me/upl30_bot)
- **Язык игры:** украинский. Техническая документация — на русском.

## Структура репозитория

```
upl-30-0/
├─ index.html          сайт целиком (генерируется из src/, руками не править)

├─ vercel.json         настройки Vercel
├─ api/                серверные функции Vercel: бот, вход, лиги, cron, seed, запись результатов (save), проверка сезона, картинка; _device.js — общее (не адрес)
├─ lib/engine.js       серверный движок симуляции (генерируется, руками не править)
├─ src/                ИСХОДНИКИ ИГРЫ
│  ├─ template.html    основа: разметка, стили, игра, таблицы
│  ├─ account.js       вход, профиль игрока, имена, лиги групп
│  ├─ challenge.js     «Виклик другу» по ссылке
│  ├─ five.js          режим 5×5 (локально и онлайн)
│  ├─ trophies.js      трофеи
│  ├─ icons.js         иконки (генерирует src/icons/make_icons.py)
│  ├─ pool.json        все игроки и сезоны с рейтингами
│  └─ build.py         сборка → ../index.html и ../dist/30-0-upl.html
├─ sql/                все SQL по версиям; база с нуля: new_db_part_A.sql + v039_part_B.sql + cards_bucket.sql + v053_writes.sql (+ v054_close_writes.sql — шаг 2)
├─ tools/              make_engine.js (движок для сервера), sim30.js (замер сложности), tests/

└─ docs/               формулы, гейм-дизайн
```

Папки `src/`, `sql/`, `tools/`, `data/` и `docs/` не публикуются на сайте (`.vercelignore`).

| Античит | seed сезона выдаёт сервер (`api/seed.js`), сервер пересчитывает сезон тем же движком (`api/verify.js`, `lib/engine.js`). В таблицы попадают только проверенные сезоны |
| Запись результатов | с 0.53 сезоны, трофеи и «Виклик другу» пишет сервер (`api/save.js`) после проверки секрета устройства (`device_ok` в базе); результат дня — сервер из проверенного сезона. DECISIONS п. 16 |

**Какую базу берёт сайт:** на адресе ветки `test` (`…-git-test-…vercel.app`) или с `?db=test` — тестовую, и у логотипа видна метка «ТЕСТ». Везде остальное — основную. Код: `SB_ENVS` в `src/template.html`.

**Переменные окружения в Vercel.** Хранятся только там, в репозиторий и в чаты не попадают.

| Переменная | Production | Preview (тест) |
|---|---|---|
| `TG_TOKEN`, `TG_BOT` | ✓ | `TG_TOKEN` ✓ |
| `TG_SECRET` | ✓ **обязательно** (тот же, что в вебхуке бота) | ✓ **обязательно** (любое длинное значение) |
| `CRON_SECRET` | ✓ **обязательно** (с 0.52) | ✓ **обязательно** (с 0.52) |
| `SUPABASE_SERVICE_KEY` | ключ основной базы | ключ тестовой базы |
| `SUPABASE_URL` | — (по умолчанию основная) | адрес тестовой базы |
| `TEST_SUPABASE_URL`, `TEST_SUPABASE_SERVICE_KEY` | ✓ (бот пишет токены входа и в тест) | — |

С 0.52 бот и вечерний подсчёт лиг работают только с секретом: `api/bot.js` отвечает 401, если `TG_SECRET` не задан или не совпал; `api/cron.js` — если не задан `CRON_SECRET` (Vercel Cron сам шлёт его в заголовке `Authorization: Bearer …`). Запустить подсчёт вручную ссылкой `?key=…` больше нельзя.

**Как добавить `CRON_SECRET` (и `TG_SECRET` для Preview) — с iPad, один раз.** Значения никому не пересылать, в чат не вставлять.
1. Придумай секрет: в Safari на любой странице с полем пароля iPad предложит «Надёжный пароль» — скопируй его. Или любые 30+ случайных букв и цифр.
2. Открой vercel.com → проект **upl-30-0** → вкладка **Settings** → слева **Environment Variables**.
3. Нажми **Add New** (или «Add Environment Variable»): Key — `CRON_SECRET`, Value — вставь секрет. В **Environments** отметь **Production** и **Preview**. Нажми **Save**.
4. `TG_SECRET`: найди его в списке. Если у него стоит только Production — **не меняй значение для Production** (оно должно совпадать с вебхуком бота). Добавь ещё одну переменную `TG_SECRET` только для **Preview** с любым другим длинным значением (бот на тестовый сайт не ходит, секрет нужен, чтобы тестовый `/api/bot` был закрыт).
5. Переменные действуют только на новые сборки: вкладка **Deployments** → последняя сборка нужной ветки → **⋯** → **Redeploy**. Для прода это сделает мерж 0.52, для теста — любой новый пуш в `test` (или Redeploy).
6. Проверка: в Safari открой `https://upl-30-0.vercel.app/api/cron` — должно быть `{"error":"unauthorized"}`. Это правильно: вызвать подсчёт может только Vercel Cron. Бот в Telegram отвечает на `/top` как раньше.

## Как выпускаем версию

1. **Claude:**
   - правит `src/`;
   - поднимает номер в подвале («Що нового у версії X.YY» в `src/template.html`) и обновляет `WHATSNEW`;
   - собирает: `python3 src/build.py` и `node tools/make_engine.js`. Номер в подвале и `VERSION` в `lib/engine.js` должны совпасть;
   - прогоняет проверки (ниже);
   - обновляет CHANGELOG и BACKLOG;
   - отправляет в ветку `test`.
2. **SQL, если есть:** новый файл `sql/<что>.sql`. Claude присылает его в чат **блоком кода**. Владелец запускает сначала в тестовой базе, после мержа — в основной. Правила базы — DECISIONS, пункт 13: только добавляем.
3. **Claude** проверяет полностью (см. CLAUDE.md → «Выпуск»): `python3 data/check_pool.py` без ошибок, `determinism` 9/9, `scenarios` «УСЕ ГАРАЗД», тестовый сайт собрался. Если есть SQL — ждёт, пока владелец выполнит его в основной базе.
4. **Claude** делает pull request `test` → `main` и мержит его сам (решение владельца 29.09.2026). Прод собирается сам. Владелец может посмотреть тестовый сайт (метка «ТЕСТ») в любой момент.
5. **Проверка прода:** внизу upl-30-0.vercel.app — новая версия. Мини-апп в Telegram закрыть и открыть заново, иначе может показывать старую версию из кэша.

## Проверки перед выпуском

Нужны Node 18+, Python 3, Playwright с Chromium (`cd tools && npm i --no-save acorn acorn-walk playwright`).
- Пул данных (с 0.54): `python3 data/check_pool.py` — инварианты `src/pool.json` (поля карточек, позиции, id, псевдонимы, `meta`, переходы посреди сезона); код выхода 1 и строки «ПОМИЛКА» при нарушении. Обязательна, если менялся пул (`data/README.md`).
- Главные, работают из репозитория как есть (открывают `index.html`, сеть кроме шрифтов заблокирована — в базы ничего не пишут):
  - `node tools/tests/determinism.js` — браузер и сервер совпали 9/9 (с 0.50 — ещё «Ліга легенд»);
  - `node tools/tests/scenarios.js` — главная, тема, 4 сезона разных форматов, голы сходятся с матчами, текст и картка; снимки в `tools/tests/out/`.
  - В облачной среде Claude Chromium ходит через прокси: `PROXY_CA_SPKI` — отпечаток ключа CA прокси (`openssl x509 -in /root/.ccr/agent-proxy-ca.crt -pubkey -noout | openssl pkey -pubin -outform der | openssl dgst -sha256 -binary | base64`).
- Остальные тесты в `tools/tests/` запускаются так же, из корня: `node tools/tests/<файл>`; каждый заканчивается строкой «УСЕ ГАРАЗД»:
  - `cheat` — античит без браузера: честный сезон проходит, все подделки отклоняются;
  - `modes` — режимы и форматы; `tro` — трофеи; `chal` — виклик другу; `leagueui` — лиги групп; `news` — «Що нового» и вход; `f5test2`, `f5online` — 5×5;
  - `v39` — профиль игрока, таблица, проверка сезона: браузер против базы в памяти (`_site.js`) и настоящих `api/*.js`; `node tools/tests/v39.js [new|old|both]`.
- `bash tools/tests/setup.sh` — SQL на временном Postgres (заглушка Supabase `stub.sql`): повторный запуск `new_db_part_A.sql`, `v039_part_B.sql`, `cards_bucket.sql`, `v053_writes.sql`, `v054_close_writes.sql`, RLS и функции игрока, секрет устройства (К6), общий телефон (В6), закрытие прямой записи (шаг 2).

## Первый запуск в Claude Code (один раз)

Исходники и данные до 29.09.2026 лежали только в рабочей папке чата. Чтобы перенести их в репозиторий, владелец загрузил архив `upl-30-0-source.zip` в корень `main`. Первая задача новой сессии:
1. Распаковать архив в корень репозитория. Файлы сайта (`index.html`, `api/`, `lib/`) в нём такие же, как в репозитории.
2. Удалить архив из репозитория.
3. Проверить, что `python3 src/build.py` и `node tools/make_engine.js` дают те же `index.html` и `lib/engine.js`, байт в байт.
4. Отправить в ветку `test` и создать pull request в `main`.
