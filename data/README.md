# Данные: как получается `src/pool.json`

Документ описывает пайплайн **как он есть сейчас** (0.57). Главное правило — в конце: «Правило на будущее».

## Коротко

`src/pool.json` — не результат одной команды, а **накопленное состояние**: снимок v1, собранный в Colab из Википедии,
Transfermarkt (Kaggle) и sports.ru (этапы 1–5, сентябрь 2026), перенесённый в репозиторий 29.09.2026 (коммит `e45ea8b`),
и дальше менявшийся только скриптами из раздела «Текущие скрипты». Пересобрать пул «с нуля» из сырья нельзя и не нужно:
старые скрипты ссылаются на чужие папки (`/content/drive/…`, `/home/claude/upl-dataset/…`, `game/pool.json`) и при повторном
запуске перезаписали бы пул старой версией (без позиций, ноги, исправлений 2021/22, сжатой шкалы).

Формат карточки: `[имя, линия GK/DF/MF/FW, рейтинг, матчи, голы, person_id, основная позиция, дополнительные, ассисты|null,
сухие|null, гражданство (индекс в nats или -1), год рождения]`. Остальные ключи пула: `clubs`, `seasons`, `meta`, `nats`,
`foot` (рабочая нога), с 0.54 — `alias` (псевдонимы id).

## Псевдонимы: один человек — два id (0.54)

Номера футболистов не меняются никогда (DECISIONS п. 7). Если один человек попал в пул под двумя id (разные источники,
ошибка в дате рождения), дубль остаётся в карточках, а в `aliases/aliases.csv` добавляется строка
`dup_id, canonical_id, name, evidence` (доказательство обязательно). `aliases/apply.py` пишет `pool['alias'] = {dup: canonical}`.
Игра сравнивает людей по canonical id: «гравець двічі» (`S.taken` в браузере и `api/verify.js` на сервере), 5×5, трофеи
(клубы человека — общие), счётчик футболистов. С 0.57 по canonical id считаются и рейтинги: сглаживание камео, класс, пики владельца.

Кандидаты на новый псевдоним ищутся так: одинаковое имя (без апострофов, в нижнем регистре) + год рождения совпадает или
отличается на 1/10 + сезоны не пересекаются; подтверждение — полная дата и Transfermarkt ID (Wikidata P2446), клубы, отчество
в сыром ряду `data_v2/ratings_player_seasons.csv`. Непроверенные кандидаты — в BACKLOG, не в `aliases.csv`.

## Цвета клубов: `club_colors.csv` (0.56)

`code` = `c` в `pool.json`, `c1` — заливка фишки, `c2` — обводка, `c3` — запасной цвет текста. В пул не входит: `src/build.py` встраивает таблицу в `index.html` константой `CLUB_COLORS`. Клуб без `c1` (Темп) — нейтральная фишка. Новый клуб в пуле — добавить строку (проверка покрытия — в отчёте 0.56, CHANGELOG).

## Проверка пула: `check_pool.py`

Жёстко (exit 1): 12 полей нужных типов; рейтинг 45–99; id формата `tm:<N>` / `w:<дата>:<латиница>`, в клуб-сезоне один раз;
основная позиция — одна из 15, линия GK ⇔ основная GK; у одного id одинаковые имя, год рождения, гражданство; команды сезона ⇔
клуб-сезоны; ключи `foot` есть в пуле; `alias` без ланцюжков и с существующими id; `meta` = реальные счётчики; человек (canonical)
в двух клубах одного сезона — только если переход есть в `data/check_pool_transfers.csv`.

Белый список переходов посреди сезона (`check_pool_transfers.csv`) — снимок 0.54 (930 пар «сезон — человек»), вручную не
проверялся весь; строки, где сумма матчей больше туров сезона, помечены (`note`) и печатаются как «увага». Новый переход
(например, после исправления данных) скрипт считает ошибкой: проверь его по источнику и только потом
`python3 data/check_pool.py --write-transfers`.

## Правило на будущее

1. База — текущий `src/pool.json` (снимок v1 + скрипты выше). Пул руками не правим.
2. Любое изменение данных — **идемпотентный скрипт** с путями от корня репозитория (`os.path.dirname(__file__)`), который
   ищет карточку и «до», и «после» правки и при повторном запуске ничего не меняет. Id не меняются и не исчезают (п. 7);
   картки не переставляются (ключи `pool_ratings_raw.json` — «год|клуб|индекс»), новые — только в конец клуба.
3. У каждого значения — источник (url или файл-сырьё) в самом скрипте или в CSV рядом.
4. Новый скрипт — строкой в таблицу «Текущие скрипты» здесь, в нужном месте порядка.
5. После любой правки: `python3 data/update_meta.py && python3 data/check_pool.py`, сборка, `determinism` 9/9; если менялись
   рейтинги или позиции — замер `tools/sim30.js` и запись в DECISIONS (CLAUDE.md).
